Route: `/bing-insights`.

## What it does

The Bing equivalent of [GSC Insights](/docs/connected-data/gsc-insights): headline metric
cards (clicks, impressions, average CTR, average position), a traffic trend
chart, and a sortable daily-performance table, filterable to the last 7, 28,
or 90 days. Query/page-level breakdowns aren't built yet — v1 mirrors GSC
Insights' original (pre-tabs) shape.

This is **not** the connect flow — Bing auth lives entirely on
[Integrations](/docs/connected-data/integrations) as a single workspace API key, not
per-project OAuth. Bing Insights only reads that key's configured state and
lets each project pick which of the key's verified sites it reports on.

## Auth model: one global API key, not OAuth

Unlike GSC/GA4/GBP/Merchant Center, Bing Webmaster Tools has no per-project
OAuth connection — `BING_WEBMASTER_API_KEY` is one key for the whole
self-hosted deploy (get it from Bing Webmaster Tools → Settings → API
access), same shape as `GOOGLE_PAGESPEED_API_KEY`. `isBingConfigured()`
(`@rosterseo/bing`) gates every real call; the page shows an `EmptyState`
plus a destructive `Alert` when it's unset.

Once configured, each project independently picks **which verified Bing
site** it reports on via `BingSitePicker`
(`apps/web/components/bing-insights/bing-site-picker.tsx`), a real
`GetUserSites` call — saved to `projects.bing_site_url`.

## What's real today

- **`listBingSites()`** and **`getBingRankAndTrafficStats(siteUrl, startDate, endDate)`**
  (`@rosterseo/bing`, `packages/bing/src/client.ts`) — real calls against
  `https://ssl.bing.com/webmaster/api.svc/json/{Method}`
  (`GetUserSites` / `GetRankAndTrafficStats`). Bing's real method takes no
  date-range params and returns its own available window server-side, so
  the days filter (7/28/90) is applied **client-side** in
  `getBingRankAndTrafficStats`, unlike GSC's adaptive `fetchGscExactWindow`
  — GA4-style near-real-time data, no lag-trimming needed.
- **Live-tested against a real Bing Webmaster Tools account**, which
  surfaced two real-response quirks the published API docs don't call out:
  Bing's legacy WCF/ASP.NET Data Services endpoint wraps every payload in a
  top-level `d` property (`{ "d": [...] }`, sometimes further nested as
  `{ "d": { "results": [...] } }`) instead of returning a bare array — a
  bare-array parse crashed with `"(data ?? []).map is not a function"`
  until `unwrapBingArray` was added to unwrap whichever shape shows up. Its
  `Date` fields also come back in the old ASP.NET JSON date format —
  `/Date(1234567890000)/` (epoch milliseconds, sometimes with a
  `-0700`-style timezone suffix) — not ISO 8601, which threw `"Invalid time
  value"` until `parseBingDate` was added to parse that format explicitly
  (with a plain ISO fallback for any future/different Bing endpoint that
  sends one). Both fixes live in `packages/bing/src/client.ts`.

## Files

- `apps/web/app/(dashboard)/bing-insights/page.tsx` — server component;
  resolves the current project, `isBingConfigured()`, and (when a site is
  picked) the real `getBingRankAndTrafficStats` call.
- `apps/web/components/bing-insights/bing-site-picker.tsx` — real
  `GetUserSites` picker, saves to `projects.bing_site_url` via
  `PATCH /api/projects/:projectId/bing-insights`.
- `apps/web/components/bing-insights/bing-insights-workspace.tsx` — client
  component; metric cards, trend chart, daily table, date-range `Select`.
- `apps/web/components/bing-insights/bing-insights-metrics.ts` — the same
  period-over-period half-window aggregation GSC/GA Insights use.
- `apps/web/app/api/projects/[projectId]/bing-insights/sites/route.ts`,
  `apps/web/app/api/projects/[projectId]/bing-insights/route.ts` — `GET`
  (sites list / performance) and `PATCH` (save chosen site).

## Notable follow-up work (not built in this pass)

- No query/page-level breakdown yet — GSC Insights' Striking
  distance/Queries/Pages tabs don't have a Bing equivalent.
- Bing's real reporting lag/window behavior hasn't been observed live; if
  it turns out to need GSC-style adaptive trimming, `fetchGscExactWindow`'s
  approach (`apps/web/lib/gsc-fetch.ts`) is the template to reuse.
