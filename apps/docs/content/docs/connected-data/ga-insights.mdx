Route: `/ga-insights`.

## What it does

The performance **view** for a project's GA4 connection, scoped specifically
to **Organic Search** traffic — not a general-purpose GA4 dashboard. This is
an SEO tool, so what matters is how search-driven traffic is actually
performing: headline metric cards (organic sessions, engagement rate,
average engagement time, conversions), a sessions trend chart, a date-range
selector (last 7/28/90 days), and a tabbed breakdown table — Landing pages,
Devices, and Countries.

The landing-pages tab is the actionable one: sessions, engagement rate,
average duration, and conversions per page, ranked by sessions. A
high-traffic page with poor engagement is worth investigating (content
mismatch with what search sent people looking for); a page converting well
from organic is worth studying and replicating elsewhere. The Devices and
Countries tabs surface the same metrics split by device category
(desktop/mobile/tablet) and country — low mobile engagement on a
mobile-heavy site, or a geography search is bringing in traffic from
without converting, are both signals a single blended number would hide.

This is **not** the connect flow — connecting/disconnecting Google (GSC and
GA4) stays entirely on [Integrations](/docs/connected-data/integrations). GA Insights only
reads the connection state and picks a property if one hasn't been chosen
yet; it never renders a Connect/Disconnect button itself.

## Shared connection state with Integrations and GSC Insights

Connection status is computed through the same `toConnectionStatus()`
helper (`apps/web/lib/google-connection-status.ts`), querying the real
`google_connections` table by the current project's *organization* — the
same pattern [GSC Insights](/docs/connected-data/gsc-insights) uses for GSC. No surface can
disagree about whether the org's GA4 connection is live. The page shows its
data view only when **all** of these are true:

- `isGoogleOAuthConfigured()` is `true`.
- The organization's `google_connections` row for `service: "ga4"` has
  `status: "connected"` — a real `needs_reconnect` flag, not an
  access-token expiry check (see [Integrations](/docs/connected-data/integrations)'s
  token-refresh section) — shared across every project in the org.
- This project's own `ga4_property_id` is set. If not, the page shows
  `PropertyPicker` (`apps/web/components/integrations/property-picker.tsx`,
  service `"ga4"`) instead — a real dropdown of the connected account's GA4
  properties.

Otherwise it renders `EmptyState` (plus an `Alert` when OAuth isn't
configured) with a link back to `/integrations`. A failed live API call
(revoked access, or the Analytics Data API not yet enabled on the Google
Cloud project) shows the same "needs reconnecting" empty state via a
`fetchFailed` flag — the same error-handling path `PropertyPicker` already
has for the "API not enabled" case applies here too, since GA4 property
listing uses the same route.

## What's real today

There is no mock path here at all — GA4 data-fetching didn't exist before
this page, so it was built real from the start:

- **`getGA4OrganicTrend`**, **`getGA4TopLandingPages`**,
  **`getGA4DeviceBreakdown`**, and **`getGA4CountryBreakdown`**
  (`@rosterseo/google`, `packages/google/src/ga4-performance.ts`) — four real
  Analytics Data API `runReport` calls (`analyticsdata.properties.runReport`),
  fired in parallel and all filtered to
  `sessionDefaultChannelGroup = "Organic Search"` via a shared
  `dimensionFilter` — a standard GA4 dimension, no custom event setup
  required. `getGA4DeviceBreakdown` dimensions by `deviceCategory`
  (desktop/mobile/tablet); `getGA4CountryBreakdown` dimensions by `country`,
  capped at the top 25 by sessions. The `accessToken` for all four comes
  from `getValidAccessToken()` (`apps/web/lib/google-token.ts`), which
  transparently refreshes a stale one via `refresh_token` first — see
  [Integrations](/docs/connected-data/integrations)'s token-refresh section.
- **The date range is user-adjustable** — a `FilterSelect` (7/28/90 days,
  default 28) drives `GET /api/projects/:projectId/ga-insights?days=N`,
  which re-runs all four real Analytics Data API calls for the new window
  via `getDateRange()` (`apps/web/lib/date-range.ts`) and returns fresh
  trend/landing-page/device/country rows.
- No extra OAuth scope was needed: `analytics.readonly` (already requested
  for GA4 connect) covers the Data API the same way it covers the Admin API
  `listGA4Properties()` uses for the property picker.
- **Metric-card deltas** ("+N% vs prior 15d", etc.) are computed by
  `summarizeGaOrganicTrend()` (`apps/web/components/ga-insights/ga-insights-metrics.ts`),
  the same half-window period-comparison technique GSC Insights'
  `summarizeSearchConsoleRows()` uses on the currently-loaded window of real
  rows — not shared between the two since GSC and GA4 rows have different
  fields.
- Like GSC Insights, GA4's Data API withholds the most recent 1–3 days as
  not-yet-finalized. The page computes how many days behind the real data
  actually is and states it directly under the chart ("Google Analytics
  hasn't finalized the last N days yet") rather than just looking stale.

## Files

- `apps/web/app/(dashboard)/ga-insights/page.tsx` — server component;
  resolves the current project, real connection status, and (when
  possible) the initial four real report calls for the default 28-day
  window, then renders the empty state, the property picker, or the
  workspace.
- `apps/web/app/api/projects/[projectId]/ga-insights/route.ts` — `GET`
  route backing the date-range selector; re-runs all four real Analytics
  Data API calls for the requested `days` (7, 28, or 90) and returns fresh
  trend/landing-page/device/country rows.
- `apps/web/components/ga-insights/ga-insights-workspace.tsx` — client
  component; metric cards, trend chart, date-range selector, and the
  `DataTable` column definitions for all three tabs (Landing pages,
  Devices, Countries) — cell renderers can't cross the Server → Client
  Component prop boundary, so column construction has to live client-side.
- `apps/web/components/ga-insights/ga-insights-metrics.ts` — the
  period-over-period aggregation described above.
- `apps/web/components/charts/organic-sessions-chart.tsx` — recharts
  `AreaChart`, same setup as `traffic-chart.tsx` but plotting GA4's
  `sessions` field instead of GSC's `clicks`/`impressions`.
- `apps/web/lib/date-range.ts` — `getDateRange(days)`, the shared
  `{ start, end }` ISO-date helper both the page and the API route use.
