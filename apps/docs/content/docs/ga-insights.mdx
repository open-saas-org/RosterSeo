Route: `/ga-insights`.

## What it does

The performance **view** for a project's GA4 connection, scoped specifically
to **Organic Search** traffic — not a general-purpose GA4 dashboard. This is
an SEO tool, so what matters is how search-driven traffic is actually
performing: headline metric cards (organic sessions, engagement rate,
average engagement time, conversions), a sessions trend chart, and a
sortable table of the top organic landing pages.

The landing-pages table is the actionable part: sessions, engagement rate,
average duration, and conversions per page, ranked by sessions. A
high-traffic page with poor engagement is worth investigating (content
mismatch with what search sent people looking for); a page converting well
from organic is worth studying and replicating elsewhere.

This is **not** the connect flow — connecting/disconnecting Google (GSC and
GA4) stays entirely on [Integrations](/docs/integrations). GA Insights only
reads the connection state and picks a property if one hasn't been chosen
yet; it never renders a Connect/Disconnect button itself.

## Shared connection state with Integrations and GSC Insights

Connection status is computed through the same `toConnectionStatus()`
helper (`apps/web/lib/google-connection-status.ts`), querying the real
`google_connections` table by the current project's *organization* — the
same pattern [GSC Insights](/docs/gsc-insights) uses for GSC. No surface can
disagree about whether the org's GA4 connection is live. The page shows its
data view only when **all** of these are true:

- `isGoogleOAuthConfigured()` is `true`.
- The organization's `google_connections` row for `service: "ga4"` has
  `status: "connected"` — a real `needs_reconnect` flag, not an
  access-token expiry check (see [Integrations](/docs/integrations)'s
  token-refresh section) — shared across every project in the org.
- This project's own `ga4_property_id` is set. If not, the page shows
  `PropertyPicker` (`apps/web/components/integrations/property-picker.tsx`,
  service `"ga4"`) instead — a real dropdown of the connected account's GA4
  properties.

Otherwise it renders `EmptyState` (plus an `Alert` when OAuth isn't
configured) with a link back to `/integrations`. A failed live API call
(revoked access, or the Analytics Data API not yet enabled on the Google
Cloud project) shows the same "needs reconnecting" empty state via a
`fetchFailed` flag — the same error-handling path `PropertyPicker` already
has for the "API not enabled" case applies here too, since GA4 property
listing uses the same route.

## What's real today

Unlike most of this app's data-heavy modules, there is **no mock path**
here at all — GA4 data-fetching didn't exist before this page, so it was
built real from the start:

- **`getGA4OrganicTrend(accessToken, propertyId, startDate, endDate)`** and
  **`getGA4TopLandingPages(accessToken, propertyId, startDate, endDate, limit?)`**
  (`@seo-tool/google`, `packages/google/src/ga4-performance.ts`) — real
  Analytics Data API `runReport` calls (`analyticsdata.properties.runReport`),
  both filtered to `sessionDefaultChannelGroup = "Organic Search"` via a
  `dimensionFilter` — a standard GA4 dimension, no custom event setup
  required. The `accessToken` comes from `getValidAccessToken()`
  (`apps/web/lib/google-token.ts`), which transparently refreshes a stale
  one via `refresh_token` first — see [Integrations](/docs/integrations)'s
  token-refresh section.
- No extra OAuth scope was needed: `analytics.readonly` (already requested
  for GA4 connect) covers the Data API the same way it covers the Admin API
  `listGA4Properties()` uses for the property picker.
- **Metric-card deltas** ("+N% vs prior 15d", etc.) are computed by
  `summarizeGaOrganicTrend()` (`apps/web/components/ga-insights/ga-insights-metrics.ts`),
  the same half-window period-comparison technique GSC Insights'
  `summarizeSearchConsoleRows()` uses — not shared between the two since
  GSC and GA4 rows have different fields.
- The last 30 days is a fixed window for now, same convention as GSC
  Insights.

## Files

- `apps/web/app/(dashboard)/ga-insights/page.tsx` — server component;
  resolves the current project, real connection status, and (when
  possible) both real report calls, then renders the empty state, the
  property picker, or the workspace.
- `apps/web/components/ga-insights/ga-insights-workspace.tsx` — client
  component; metric cards, trend chart, and the landing-pages `DataTable`
  (column definitions have to live client-side — cell renderers can't
  cross the Server → Client Component prop boundary).
- `apps/web/components/ga-insights/ga-insights-metrics.ts` — the
  period-over-period aggregation described above.
- `apps/web/components/charts/organic-sessions-chart.tsx` — recharts
  `AreaChart`, same setup as `traffic-chart.tsx` but plotting GA4's
  `sessions` field instead of GSC's `clicks`/`impressions`.

## Notable follow-up work (not built in this pass)

- A non-organic channel comparison (e.g. organic's share of total traffic)
  would need a third, unfiltered `runReport` call — deliberately out of
  scope for this pass, which is organic-only by design.
- The date range (last 30 days) isn't user-adjustable yet.
