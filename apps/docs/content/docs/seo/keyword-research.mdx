Route: `/keyword-research`.

## What it does

Enter a seed keyword and a location, get a real seed-keyword summary
(volume, CPC, competition, intent, difficulty) plus up to 50 real keyword
results in one filterable, sortable, bulk-selectable table, ordered
similar-first: real "searches related to" matches, then real substring
variations of the seed, then (only if those two are thin) broader
same-category ideas. Clicking any keyword shows a real 12-month volume
trend chart and a real top-10 SERP preview for it in a side panel. Three
tabs — Similar, Suggested, Questions — are non-exclusive lenses over that
same result set rather than a strict partition; which tab a row shows up
under is how you tell its source tier apart, not a per-row badge or
column. Every keyword the search returns - not just ones the user
tracks - is saved to the database, and every search itself is logged so
past searches are revisitable from a "Recent searches" list.

This is a full rebuild, not the original version. The original page called
an unauthenticated Server Action directly from the client with zero
persistence, and its "keyword ideas" were never real - just the seed
keyword with 10 hardcoded suffixes ("best", "free", "vs"...) appended and
re-looked-up, and "questions" were 4 hardcoded string templates. The
location dropdown was also cosmetic: the real DataForSEO call underneath
always used a hardcoded US location code regardless of what was selected -
which is very likely why real searches for non-US-relevant keywords kept
returning "no data" and silently falling back to mock output, the exact
bug that prompted this rebuild.

## What's real vs mock today

- **Keyword results**: real, tiered, real-only - none of the three
  DataForSEO Labs functions behind this grid has a mock fallback; a
  failed/unconfigured call returns an honest empty list, never
  fabricated-looking results (this is now the convention across the whole
  `@rosterseo/dataforseo` package, not an exception specific to these
  three). `getRelatedKeywords()` (Labs `related_keywords` - Google's actual
  "searches related to" matches) and `getKeywordSuggestions()` (Labs
  `keyword_suggestions` - real substring variations of the seed) run
  together and are shown first, in that order; `getKeywordIdeas()` (Labs
  `keyword_ideas` - broader same-category matches) only runs as a third
  tier when the first two together return fewer than 15 results. Each
  result carries a `source` tag (`related`/`suggestion`/`idea`) internally —
  it drives which of the three tabs a row appears under (see above) and is
  included in CSV export, but isn't rendered as its own column or badge in
  the table itself. These three functions are also used
  outside this page - the Cappy assistant's read tool
  (`apps/web/lib/cappy/tools/read.ts`) and the MCP server
  (`apps/mcp-server/src/index.ts`) both call all three the same way.
- **Seed keyword metrics and location**: real, and now actually
  location-aware. `getRealKeywordMetrics()` gained an optional
  `locationCode` parameter (previously hardcoded to US/2840 internally) -
  Keyword Research passes the real selected location code through; Page
  Analyzer's existing single-keyword call is untouched (parameter is
  optional, defaults to US). Rank Tracking's metrics-refresh call site
  (`apps/worker/src/features/rank-check-runner.ts`) was also fixed to pass
  its project's real configured location instead of the same implicit
  US default - a second instance of the identical bug, fixed alongside
  this one.
- **SERP preview**: real, via `checkKeywordRanking()` (the same function
  Rank Tracking uses) - not the older free-text-location `getSerpResults()`,
  which only resolves a location through a crude ~19-country name map and
  would silently default to US for the numeric location codes this page's
  picker produces.
- **Persistence**: real. Two new tables - `keyword_metrics_cache` (every
  keyword any search returns gets upserted here, keyed by
  project+keyword+location; a repeat search for an already-cached,
  still-fresh keyword within 7 days skips DataForSEO) and
  `keyword_research_searches` (a real log of every search run, powering
  "Recent searches"). Not built: a full per-search result-snapshot table -
  reopening a past search from history re-runs the real idea-generation
  call rather than replaying an exact frozen result set; only the
  per-keyword metrics are guaranteed to come from cache on a repeat.
- **Question classification**: not a separate API call. A keyword counts
  as a question if it starts with a common question word (how/what/why/
  when/where/who/which/can/does/do/is/are/will/should) - pure client-side
  regex (`isQuestionKeyword()`, `apps/web/components/keywords/question-classifier.ts`)
  over the same real tiered results already fetched, applied across all
  three source tiers, not just `keyword_ideas`.
- **The Track button**: real, unchanged in destination -
  `POST /api/projects/:projectId/keywords` (the same route
  [Rank Tracking](/docs/seo/rank-tracking) reads from). The client no longer
  sends a `location` field (that route already silently ignored it -
  location is a project-wide Rank Tracking setting now, not per-keyword),
  and the tracked-state check is keyed by keyword alone instead of
  `keyword|location` to match.

## Database tables

Both new, in `packages/db/src/app-schema.ts`, RLS-protected the same way as
Rank Tracking's `rank_check_runs` (direct `project_id` column policy):

- **`keywordMetricsCache`** (`keyword_metrics_cache`) - `projectId`,
  `keyword`, `locationCode`, `searchVolume`, `keywordDifficulty`, `cpc`,
  `intent`, `monthlySearches` (jsonb, last 12 months), `fetchedAt`. Unique
  on `(projectId, keyword, locationCode)`.
- **`keywordResearchSearches`** (`keyword_research_searches`) - `projectId`,
  `seedKeyword`, `locationCode`, `locationName`, `resultCount`, `createdAt`.

## API routes

### `GET /api/projects/:projectId/keyword-research`

Lists the 20 most recent `keyword_research_searches` rows for the project.

### `POST /api/projects/:projectId/keyword-research`

Body: `{ seedKeyword, locationCode, locationName }`. The only route that
calls DataForSEO for this feature - real `getRealKeywordMetrics()` for the
seed (cache-checked first, skipping DataForSEO on a still-fresh cache hit)
plus the tiered `getRelatedKeywords()` / `getKeywordSuggestions()` /
`getKeywordIdeas()` fetch for the results grid, upserts every returned
keyword into `keyword_metrics_cache`, logs one
`keyword_research_searches` row, returns `{ seed, results }`.

### `GET /api/projects/:projectId/keyword-research/serp?keyword=...&locationCode=...`

Real top-10 organic SERP for one keyword, via `checkKeywordRanking()`.
